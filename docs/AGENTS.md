## Running commands

```powershell
ucp-cli ping                                   # after ucp-cli/setup.ps1; else node ucp-cli/bin/ucp-cli.js
ucp-cli run <type> [--args '{"key":"value"}']
ucp-cli help [<type>] [--md]                   # catalog, or one command's card
ucp-cli run-script flow.json                   # several commands, stops at the first failure
ucp-cli host status
```

- **Project selection:** `--project <path>`; with one Editor open it is picked automatically.
- **Timeouts:** omit `--timeout` and each command uses its own default (`build` 30 min,
  `test_run` 10 min, `compile` 180 s, most others 30 s).
- **Host port:** `UCP_HOST_PORT` (default `6610`).
- **Integration tests:** `UCP_EDITOR_INTEGRATION=1` + Unity Editor open; see
  [MAINTENANCE.md](MAINTENANCE.md#node-development).

## Reading results

- `ok: false` always comes with `error_code`, `message`, and usually `hint`. Branch on the code,
  show the message, follow the hint. `ucp-cli help <type>` lists a command's codes (`node_not_found`,
  `play_mode_required`, `invalid_argument`, `busy`, ...).
- Codes from ucp-host rather than Unity: `no_ready_session`, `editor_not_running`,
  `unknown_command`, `timeout`, `host_lost`, `unauthorized`; the full table is in
  [CHANGELOG_AGENT.md](CHANGELOG_AGENT.md#upgrading-from-03).
- After `timeout` or `host_lost` the command may still have run: check with a read command before
  sending a non-idempotent one (`gameobject_create`, `exec`) again.
- `node_not_found` hints the closest sibling names; `timeout` hints whether Unity was in the
  background (it then ticks about 10 times a second).
- Tree and snapshot reads are capped (`limit`, default 500); `truncated: true` means there is more.
- `ping`, `state`, `console`, `help` and `echo` do not wait for another command (a test run, a
  compile) to finish; other commands wait their turn. During a domain reload itself nothing
  answers until it is over, a few seconds.

## Quick facts

- **No profiles**, no `POST /list`, no `~/.unity-cmd/`.
- **Command names:** lowercase `{domain}_{operation}`; constants in `CommandNames.cs`.
- **Command catalog:** `ucp-cli help`, generated by `CommandRegistry` from the loaded assemblies.
- **Add command:** constant in `CommandNames.cs` + params in `Editor/Params/` + logic in
  `Editor/Services/` + an `EditorActionCommand<T>` shell in `Editor/Commands/`. See
  [MAINTENANCE.md](MAINTENANCE.md).
- **Editing project content:** `gameobject_*` / `component_*` take an optional `prefab` argument —
  with it they edit that prefab asset in place, without it the open scene. Same commands, one
  implementation (`Editor/Services/Objects/EditTargetScope.cs`). `prefab` only ever names that
  edit target; `prefab_*` asset commands take `path`, and a prefab to instantiate or render is
  `source`. For several edits, use `prefab_edit` / `scene_edit` with `ops: [{command, args,
  expect?}]`: one save, nothing kept on failure; `dry_run` shows the result without keeping it.
- **Checking the game:** `play`, then `ui_snapshot` / `ui_click` / `ui_input` / `ui_wait` with
  node paths as `ui_snapshot` prints them, then `stop`. `test_run` runs the project's tests.
- **After C# changes:** `ucp-cli run compile`; it imports changed files first and fails as
  `compile_error` with the compiler's errors.
- **State fields:** `agent_state`, `play_mode`, `tests_running` in `run state`.

## Do not

- Reintroduce `com.air.unity-connector` or Editor HTTP `:6547`.
- Add manual handler registration; `CommandRegistry` finds every `CliCommand` subclass.
- Maintain a markdown command catalog in this repo — use `CommandNames.cs` + discovery.
- Add multi-action commands that dispatch on an `action` parameter (that is what `manage` was, and
  it was removed in 0.4.0). One operation, one command; use `aliases` for synonyms.
- Duplicate a content operation into a separate `prefab_*` version — extend
  `GameObjectService` / `ComponentService` so both scopes get it.
- Call anything that can raise a modal dialog (unsaved-changes prompts, `EditorUtility.DisplayDialog`)
  — a modal blocks the Editor main thread, which is also the agent's poll loop. Refuse and ask the
  caller for `force` instead, as `SceneService` does.
