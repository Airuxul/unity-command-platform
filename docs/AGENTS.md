## Running commands

```powershell
ucp-cli ping                                   # after ucp-cli/setup.ps1; else node ucp-cli/bin/ucp-cli.js
ucp-cli run <type> [--args '{"key":"value"}']
ucp-cli help [<type>] [--md]                   # catalog, or one command's card
ucp-cli run-script flow.json                   # several commands, stops at the first failure
ucp-cli host status
```

- **Project selection:** `--project <path>`; with one Editor open it is picked automatically.
- **Timeouts:** omit `--timeout` and the command uses the `default_timeout_ms` on its `ucp-cli help`
  card. A null there means 30 s.
- **Host port:** `UCP_HOST_PORT` (default `6610`).
- **Integration tests:** `UCP_EDITOR_INTEGRATION=1` + Unity Editor open; see
  [MAINTENANCE.md](MAINTENANCE.md#node-development).

## Reading results

- `ok: false` always comes with `error_code`, `message`, and usually `hint`. Branch on the code,
  show the message, follow the hint. `ucp-cli help <type>` lists the agent's codes (the same table
  on every card: `node_not_found`, `play_mode_required`, `invalid_argument`, `busy`, ...).
- Codes from ucp-host rather than Unity: `no_ready_session`, `editor_not_running`,
  `host_unknown_command`, `host_timeout`, `host_command_failed`, `host_lost`, `host_restarting`,
  `host_unreachable`, `session_unavailable`, `caller_disconnected`, `unauthorized`,
  `unknown_session_type`. `host_busy` is only the answer to `POST /shutdown` while a command is in
  flight. Unity still uses `unknown_command`, `timeout`, `command_failed` and `busy` for its own
  answers. `host_restarting` and `host_unreachable` are sent again by the CLI.
- After `timeout` or `host_lost` the command may still have run: check with a read command before
  sending a non-idempotent one (`gameobject_create`, `exec`) again.
- `node_not_found` hints the closest sibling names; `timeout` hints whether Unity was in the
  background (it then ticks about 10 times a second).
- Tree and snapshot reads are capped (`limit`, default 500); `truncated: true` means there is more.
- Commands whose descriptor sets `RunsWhileBusy` still run while another command (a test run, a
  compile) is in progress. Today those are `ping`, `state`, `console`, `help` and `echo`. Other
  commands wait their turn. During a domain reload itself nothing answers until it is over, a few
  seconds.

## Quick facts

- **No profiles**, no `POST /list`, no `~/.unity-cmd/`.
- **Command names:** lowercase `{domain}_{operation}`, written on the command's descriptor.
  `CommandNames` holds a name only when other C# has to mention it. It is not the registry.
- **Command catalog:** `ucp-cli help`, generated by `CommandRegistry` from the loaded assemblies.
  Each entry has `before` and `after`. The data also has `load_errors`: command classes that did
  not load, with why. `group` runs several commands as one and takes them back when one fails.
- **Add command:** params in `Editor/Params/` (skip when there are none) + logic in
  `Editor/Services/` + a static `[UcpCommand]` class in `Editor/Commands/`. Registration is the class.
  An `Undo` only when Unity's undo does not record the change; its data goes on a context subclass.
  See [MAINTENANCE.md](MAINTENANCE.md).
- **Editing project content:** `gameobject_*` / `component_*` take an optional `prefab` argument —
  with it they edit that prefab asset in place, without it the open scene. Same commands, one
  implementation (`Editor/Services/Objects/EditTargetScope.cs`). `prefab` only ever names that
  edit target; `prefab_*` asset commands take `path`, and a prefab to instantiate or render is
  `source`. For several edits, use `group` with `steps: [{command, args, expect?}]`: one save per
  target, nothing kept on failure (`rollback=all`), or only the failed step taken back
  (`rollback=failed`, with `on_error=stop|continue`); `dry_run` shows the result without keeping
  it. Steps may include `compile` or `play`; the group carries on after the reload.
- **Static functions:** `call` runs a `[UcpFunction("name")]` static method with `args` bound by
  parameter name; `call` without `name` lists them.
- **Checking the game:** `play`, then `ui_snapshot` / `ui_click` / `ui_input` / `ui_wait` with
  node paths as `ui_snapshot` prints them, then `stop`. `test_run` runs the project's tests.
- **After C# changes:** write the file, then `ucp-cli run compile`. `compile` imports the change and fails as `compile_error` with the compiler's errors. `exec`, `play`, `test_run`, `build` and `component_add` run the scripts already loaded. Unity in the background does not import a changed script on its own, so a new component class is `type_not_found` until that `compile`.
- **State fields:** `agent_state`, `play_mode`, `tests_running` in `run state`.

## Do not

- Reintroduce `com.air.unity-connector` or Editor HTTP `:6547`.
- Add manual handler registration; `CommandRegistry` finds every `[UcpCommand]` static class.
- Maintain a markdown command catalog in this repo — `CommandRegistry` is the catalog. Add a
  `CommandNames` constant only when other C# mentions that name.
- Add multi-action commands that dispatch on an `action` parameter (that is what `manage` was, and
  it was removed in 0.4.0). One operation, one command; use `aliases` for synonyms.
- Duplicate a content operation into a separate `prefab_*` version — extend
  `GameObjectService` / `ComponentService` so both scopes get it.
- Call anything that can raise a modal dialog (unsaved-changes prompts, `EditorUtility.DisplayDialog`)
  — a modal blocks the Editor main thread, which is also the agent's poll loop. Refuse and ask the
  caller for `force` instead, as `SceneService` does.
